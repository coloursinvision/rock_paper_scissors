# Decision record 2026-10-26

Status: accepted on 2026-10-26. This is the first record and
supersedes nothing. A later record that changes a decision references
this one.

## Goal and limits

- The core feature is a model that predicts the opponent's next move.
  The decision layer plays the move with the maximum expected score,
  and every results table also reports the probability of losing.
- A uniformly random opponent cannot be beaten, and safe exploitation
  is impossible in rock-paper-scissors. Every document states both
  limits plainly.
- Risk control mixes the model's best response with uniform random
  play; the mixing weight is driven by model confidence.
- The term is hyperparameter tuning, not fine-tuning.

## Environments

- conda is the only environment manager, with conda-forge as the only
  channel and strict channel priority. Virtual environments made by
  venv or virtualenv, and the tools uv, pipenv, poetry and pixi, are
  not used.
- There are two environments: a lean one for the command-line game,
  the tests, the linter and the type checker, with no machine-learning
  library, and one for the notebooks and the tuning.
- Each environment has an environment.yml, the single source of its
  dependencies, and a lock file with integrity hashes, installed in
  frozen mode locally and in CI. pyproject.toml lists runtime
  dependencies only; the game has none.
- The project is installed into an environment with pip, without
  dependencies, without build isolation and without an index, so that
  nothing comes from PyPI.
- conda runs link scripts at install time. Each environment is audited
  for them, and CI fails on a link script that the project has not
  accepted.

## Model opponent

- The opponent runs in pure Python with no machine-learning dependency.
  An original tree evaluator reads the documented JSON exports of
  XGBoost, LightGBM and CatBoost.
- Parity tests compare the evaluator with each library's predict_proba
  on thousands of rows with a tolerance of about 1e-6, in the conda CI
  job. A model that fails parity is not exported.
- Every model ships with a manifest: library version, feature schema
  version and checksum.

## Tuning protocol

- A test population is frozen before tuning and used once.
- Nested cross-validation is grouped by match.
- Optuna's TPE sampler is compared with random search over several
  seeds, with Hyperband pruning, PED-ANOVA importance, temperature
  calibration, the Nadeau-Bengio corrected t-test and confidence
  intervals over matches.
- The baselines, a Markov predictor and a decision tree, are tuned with
  the same budget as LightGBM, CatBoost and XGBoost.
- Not used: MLflow, GPSampler, optuna-dashboard, ONNX.

## Optional opponent backed by a hosted model

- Responses API, key from OPENAI_API_KEY, store=False, a 15 second
  timeout, fallback to a random move, and a dated model snapshot
  checked for availability and price on the day of implementation.
- Sending moves to the provider is a transfer to a third party even
  with store=False; the README states it.

## Repository conventions

- The repository, the distribution and the console command are named
  rock_paper_scissors; python -m rock_paper_scissors runs the same
  command.
- All names are snake_case, except names fixed by a tool or a standard:
  class names in CapWords and constants in upper case (PEP 8),
  multi-word command-line options in kebab-case, dates as YYYY-MM-DD,
  release tags as vX.Y.Z, and file names such as README.md,
  pyproject.toml and environment.yml.
- requires-python is 3.12 or later. CI runs the full supported Python
  range on Linux and the oldest and newest supported versions on
  Windows and macOS.
- Commits are signed with SSH keys.
- Notebooks are committed only as jupytext py:percent files; .ipynb
  files are ignored.
- A few SVG figures for the README are committed, without tool
  metadata and generated by one command.
- QuitGameError stays. Human games are not logged in the first version.
- The repository holds original work only: no material from, and no
  mention of, external courses or other projects' bots. Benchmark
  opponents are original implementations of generic strategy
  archetypes.

## Unverified, to be checked before use

- Whether the newest major version of Optuna is released.
- Whether CatBoost's JSON export supports categorical features, and
  the structure of that export.
- Whether LightGBM's JSON dump has a formal schema.
- XGBoost stores thresholds as float32, so the evaluator casts features
  to float32 and the tolerance is a maximum absolute error on
  probabilities; to be confirmed against the library's documentation.
- Whether Python 3.15 is released and whether conda-forge has builds of
  the machine-learning libraries for it.
- The pinned versions of the actions used in CI.
